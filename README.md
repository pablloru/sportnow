# SportNow — V1 (MVP)

Современная веб-платформа спортивной информации и аналитики: главная страница, страницы видов
спорта, страница события с AI Match Analysis и блоком «Что изменилось?», и полноценная
демонстрационная статья. Все данные в V1 — mock data, спроектированные так, чтобы их можно было
заменить реальными API без переделки интерфейса.

## Стек и почему он выбран

- **Next.js 16 (App Router) + TypeScript** — SSR/SSG из коробки (важно для SEO), файловая
  маршрутизация один в один ложится на нужную структуру URL (`/ru/football/match/slug`),
  встроенные `metadata`/`sitemap`/`robots`.
- **Tailwind CSS 4** — быстро собрать современный, "premium" интерфейс с адаптивностью без
  большого объёма кастомного CSS.
- **next-intl** — мультиязычность через сегмент `/[locale]/` в URL. Тексты живут в
  `messages/<locale>.json`, а не в компонентах — добавление `/en/`, `/es/`, `/de/` в будущем не
  требует переписывания UI.
- Типизированный **mock-data слой** (`src/lib/mock-data`), спрятанный за репозиториями
  (`src/lib/repositories`) — когда появится реальный API, меняются только репозитории.

Подробнее об архитектуре — ниже.

## Быстрый старт

```bash
npm install
npm run dev
```

Открыть [http://localhost:3000/ru](http://localhost:3000/ru).

Проверка перед деплоем:

```bash
npm run build   # production-сборка + проверка типов
npm run lint    # ESLint
```

## Переменные окружения

Скопируйте `.env.example` в `.env.local`. Для запуска V1 на mock-данных ничего заполнять не нужно
— переменные понадобятся только когда будут подключены реальные интеграции (см. ниже).

## Архитектура

Проект разделён на 5 слоёв, каждый — отдельная папка. Не смешивайте их: компонент не должен сам
обращаться к mock-данным, а репозиторий не должен знать о React.

```
src/
├── app/                      # Presentation — маршруты и страницы (App Router)
│   └── [locale]/
│       ├── page.tsx                      # Главная
│       ├── [sport]/page.tsx              # Страница вида спорта
│       ├── [sport]/match/[slug]/page.tsx # Страница события
│       └── article/[slug]/page.tsx       # Страница статьи
├── components/               # Presentation — UI-компоненты (без бизнес-логики)
├── lib/
│   ├── services/              # Application — собирают данные для конкретного экрана
│   ├── repositories/          # Data — ЕДИНСТВЕННОЕ место, которое знает, откуда данные
│   ├── mock-data/             # Data — текущий источник (заменяется на реальный API)
│   ├── intelligence/          # Intelligence — "Что изменилось", impact scoring, прогнозы
│   ├── integrations/          # External integrations — заглушки под Sports/News/Odds API
│   └── types/                 # Общие TypeScript-сущности (Sport, Event, News, Article, ...)
├── i18n/                      # Конфигурация next-intl (locales, роутинг, навигация)
└── proxy.ts                   # Next.js 16 "proxy" (бывший middleware) — роутинг по locale
```

Поток данных: **страница → сервис → репозиторий → mock-data (сегодня) / реальный API (завтра)**.
Компоненты никогда не импортируют `mock-data` напрямую.

### Сущности данных

`Sport`, `Competition`, `Team`, `Player`, `Event` (не привязан к конкретному спорту — есть поле
`sport`), `EventStatistic`, `News`, `Article`, `Prediction`, `Injury`, `Lineup`, `Source` — все
типы описаны в `src/lib/types/entities.ts` с комментариями.

### Как подключить реальный API вместо mock data

1. Реализуйте клиент в `src/lib/integrations/` (см. `src/lib/integrations/README.md`).
2. В соответствующем файле `src/lib/repositories/*.ts` замените тело функции вызовом этого клиента
   — сигнатуры (что принимает и что возвращает функция) менять не нужно.
3. Компоненты и сервисы не трогаем — они уже написаны в терминах репозиториев.

### Добавление нового языка

1. Добавьте код языка в `routing.locales` (`src/i18n/routing.ts`).
2. Создайте `messages/<code>.json` по образцу `messages/ru.json`.

Компоненты трогать не нужно — ни один из них не содержит захардкоженного текста на русском.

### Добавление нового вида спорта

Добавьте запись в `SPORTS` (`src/lib/constants.ts`) и mock-данные для него — страницы `/[sport]`,
`/[sport]/match/[slug]` универсальны и сразу подхватят новый вид спорта.

## Что сознательно не реализовано в V1

По брифу: авторизация, личные кабинеты, платежи/подписки, букмекерские интеграции, реальный
prediction engine, real-time (WebSocket), админка, комментарии. См. `lib/integrations/README.md`
и комментарии в коде для того, где эти вещи потом подключаются.

## Демонстрационные данные

Все имена команд/игроков — вымышленные (это специально: mock-данные не должны читаться как
реальные факты, травмы или прогнозы). Изображения — сгенерированные заглушки
(`scripts/gen_placeholders.py` → `public/images/*.jpg`), не зависят от внешних сервисов.
